topophany-bar

Your whole network's status, one glance away in the macOS menu bar and on the desktop. A native companion to topo that shows what the collector concludes and never decides anything itself. It ships with six themes: the native macOS look and the TUI's own ink and phosphor, and two more built on each.

Three looks, one meaning

The same collector, three ways. The status card is always first. Everything below it is a section you can turn off or reorder. Open the playground to try every state, theme and setting.

Native · dark: an outage seen only from Seattle and San Jose

Native · light: all clear, This Mac shown as a server

Terminal: the TUI's boxed panels, degraded, with This Mac's local readings

Widgets that match the bar

Small, medium, large and extra large. Widgets are drawn by the same renderer from the same section pieces and in the same theme as the panel. See every size and state.

Themes are a renderer plus tokens

A renderer is code: it lays out sections for the panel and for each widget size. v1 has two: cards (Native) and cells (Terminal). A theme is data: a renderer's name and a token set of colors, materials and type. Adding a theme needs no code. Adding a renderer does, and every theme of that renderer comes with it. Status glyphs and what they mean belong to the renderer, so no theme can make two states look alike. Below, Aurora, Linen, Paper and Dusk are token sets only, read through the same path a theme file takes.

How it works

The app is a renderer. topo stays the brain: it holds the credentials, reads the collector and works out every row with the same code the TUI uses. They talk over a pipe, so there's no file to poll and no orphan process. When the app quits, topo sees its stdin close and exits.

Shared packages · no AppKit

TopophanyKit (frames, deadlines, requests, settings) · TopophanySections (one model per section) · TopophanyThemes (renderers, tokens, theme files) · TopophanyWidgets · LocalReadings. SwiftUI and Foundation only, so they build for any Apple platform.

Engine protocol

ProcessEngine runs topo monitor stream. A later EmbeddedEngine links the same Go core as a library and speaks the same JSON, for a sandbox that can't start a process. Nothing above the engine changes.

Widgets · App Group

A widget runs in its own process and can't read the pipe, so the app hands it the latest frame and theme through its App Group. It reloads widgets when the verdict changes, and on a slow heartbeat otherwise.

This Mac has two modes. Local readings come straight from macOS (Mach host statistics, IOKit), read by the app, never via topo and never via top. As a server is the Servers-tab card for this Mac's node, read from the collector. Separately, topo's own host check stops running top on macOS: it reads the same kernel counters in-process, still without CGO.

How much freedom

The rule: users choose what to look at, never what it means. If the bar could say "CPU over 80% is red", it would become a second, unreviewed monitoring policy that disagrees with the TUI and the webhooks.

Yours to choose Settings

  • Theme; light, dark or system
  • Menu bar: symbol, count or words; status colors or monochrome
  • Which sections appear, and their order
  • How many attention rows; which applications
  • Pinned servers; what each widget shows
  • This Mac: local readings, as a server, or off; and which readings
  • Profile, observer view, refresh (1 s to 1 h)

Fixed by Topophany topology + collector

  • What counts as up, warn, down or unknown
  • Thresholds (max_cpu_percent and others live in the topology)
  • Freshness, staleness and publisher deadlines
  • How groups add up: unknown stays in every denominator
  • Status glyphs and what they mean, in every theme
  • No expressions or formulas in templates

Not in v1

  • Local notifications (collector webhooks already alert)
  • An animated runner: the item shows status only
  • RunCat or file output; the stream replaces it
  • Loading user theme files (the format is designed; v1 ships Native and Terminal)
  • The embedded engine; history charts beyond local sparklines
