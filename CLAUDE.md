# Working in topophany-bar

topophany-bar is a native macOS menu bar app and widgets for Topophany. Before changing anything, read `design/DESIGN.md` and `docs/PROTOCOL.md`, and look at the HTML previews in `design/`. The previews are the visual reference: match them.

## Toolchain on this Mac

- **Xcode 27.1** is at `/Applications/Xcode.app`, but `xcode-select` points at the Command Line Tools. Run Xcode tools with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (e.g. `DEVELOPER_DIR=… xcodebuild …`). Don't run `sudo xcode-select`.
- **Swift and targets:** Swift 6.4 and the macOS 27 SDK. The deployment target is **macOS 26**.
- **The project:** the Xcode project is generated by XcodeGen from a committed `project.yml`. The generated `*.xcodeproj` is ignored. Install XcodeGen with Homebrew if it's missing.
- **Signing:** an Apple Development identity is in the keychain. Ask the user before using a team ID or adding signing, App Group or sandbox entitlements. Local debug builds must also work unsigned: widgets need signing, while the app itself must not.

## Architecture rules

- **Only `Apps/` imports AppKit.** Everything under `Sources/` is SwiftUI and Foundation, so it builds for any Apple platform. Describe that only as "AppKit-free"; never name other platforms or products in code, docs, comments or commits.
- **Data flows one way:** engines produce frames, sections are built from frames, and renderers take section models, never frames.
- **Themes:** a theme is a renderer ID plus tokens. Renderers own glyph shapes and meaning. Built-in themes go through the same `Theme` type a theme file would.
- **The app decides nothing.** No thresholds, no inferred health, no aggregation that `topo` didn't send. Unknown is never zero, and expired rows are withheld (`docs/PROTOCOL.md` §5).
- **Local readings are not evidence.** They have no health colors, and they are never sent anywhere.

## The `topo` side

`topo monitor stream` is being built in parallel in `~/Desktop/topophany` (branch `feat/monitor-stream`).

- **Checking for it:** `topo monitor stream --capabilities`. A dev build is at `~/Desktop/topophany/bin/topo` after `make build` there.
- **Until it exists:** use the `FixtureEngine`, which replays NDJSON fixtures written to `docs/PROTOCOL.md`.
- **Once it exists:** test against `"source":"preview"`, which needs no collector.
- **What not to do in that repo:** never edit it from here, never run its `scripts/verify.py`, and never read or write `~/Library/Application Support/topophany/credentials.json`.

## Before saying something works

- `swift build` and `swift test` for the packages.
- `xcodebuild` for the app and the widget extension.
- **Snapshot tests:** render each section, theme, state and widget size to PNG with `ImageRenderer`, and look at the images. Compare them with the matching preview, rendered by `design/shots/shot.sh`.
- **For UI changes, run the app** and capture the menu bar and the panel with `screencapture` (ask the user for Screen Recording permission if it's needed).

Report what you checked, and what you couldn't.

## Commits

Use conventional commits (`feat(panel): …`, `fix(engine): …`, `test(themes): …`) and keep each to one change. Never push, tag or create a remote unless the user asks. Never commit build products or secrets.
